# Olá, eu sou o Max (ou Sketch)

Programador desde os 11 anos, curioso por natureza e provavelmente responsável por algumas decisões questionáveis que começaram no CMD.

Comecei programando muito cedo, experimentando com comandos, scripts e pequenas coisas no Windows. Em algum momento, isso evoluiu para a criação de vírus no CMD, porque aparentemente esse era o caminho natural de uma criança curiosa com um computador.

Com o tempo, comecei a levar programação mais a sério e fui conhecendo diferentes linguagens, plataformas e formas de construir software.

Meu primeiro aplicativo de verdade foi um aplicativo Android simples para reprodução de músicas, desenvolvido em **Java nativo**.

Desde então, continuo criando projetos para aprender na prática, testar ideias e entender cada vez melhor como o software funciona por baixo dos panos.

## Criando minhas próprias ferramentas

Uma das coisas que mais gosto em programação é tentar construir as ferramentas que normalmente seriam utilizadas para construir outras coisas.

Já desenvolvi e experimentei com projetos envolvendo **game engines 2D próprias**, sistemas de ferramentas e outras tecnologias construídas do zero ou quase do zero.

A ideia não é necessariamente criar uma engine capaz de competir com grandes engines comerciais.

O objetivo é entender.

Como funciona um sistema de cenas?

Como objetos são armazenados?

Como funciona a renderização?

Como funciona a colisão?

Como uma ferramenta conversa com a engine?

Como um editor consegue modificar um projeto?

Construir essas coisas por conta própria acaba sendo uma maneira muito interessante de aprender.

Em vez de apenas escrever:


E então percebe que aparentemente decidiu criar um problema muito maior para resolver.

## Minha relação com IA

Prefiro entender o código que estou escrevendo.

Por isso, **quando posso resolver algo sozinho, prefiro escrever a solução sozinho**.

Não gosto muito da ideia de simplesmente gerar código, copiar, colar e esperar que funcione.

Prefiro pesquisar documentação, testar, errar, descobrir por que algo não funciona e corrigir.

Isso não significa que eu nunca utilize IA.

IA pode ser útil para pesquisa, explicações, brainstorming, documentação ou para ajudar a investigar um problema específico.

Mas, sempre que possível, prefiro que o código dos meus projetos seja resultado do meu próprio entendimento.

Para mim, programar não é apenas produzir código.

É aprender a pensar sobre problemas e descobrir como transformá-los em algo que realmente funciona.

## Como eu gosto de programar

### Entender antes de abstrair

Se não entendo o que uma biblioteca, sistema ou ferramenta está fazendo, tento descobrir antes de depender completamente dela.

### Resolver o problema de verdade

Código bonito é bom.

Código que funciona e resolve o problema é melhor.

### Aprender fazendo

Grande parte do que sei veio de projetos, erros, testes e muita tentativa e erro.

### Não usar tecnologia só por tendência

Uma tecnologia nova não é automaticamente melhor para todos os problemas.

### Construir minhas próprias soluções

Quando faz sentido, gosto de implementar as coisas por conta própria para entender como funcionam.

### Experimentar

Nem todo projeto precisa virar um produto.

Às vezes, construir alguma coisa simplesmente para descobrir se é possível já vale a pena.
